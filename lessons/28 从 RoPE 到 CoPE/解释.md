# 从 RoPE 到 CoPE：让位置按内容计数

“往前第5个token”和“上一句话”是两种位置。前者只需数编号，后者要先识别句子边界。CoPE把这个识别过程放进注意力：先决定哪些内容值得计数，再累加得到位置。这一讲先讲注意力中的数和向量，再用同一组例子串起RoPE、门值、位置插值与完整代码。

## 1. 注意力先算什么

Token是分词器切出的文本片段，进入模型后会查表得到一个向量，也就是一组数。模型对向量做线性变换，得到三种表示：

- **Query，Q**：当前位置用来寻找相关内容的向量。
- **Key，K**：每个候选位置提供的匹配向量。
- **Value，V**：匹配成功后，从该位置读取的内容向量。

一个query和一个key做点积：对应元素相乘再相加。例如$[1,2]\cdot[3,4]=1\times3+2\times4=11$。注意力把所有query/key配对，得到分数矩阵；再用softmax把每行分数转成和为1的权重，最后按权重混合value。

$$S=QK^T/\sqrt D,\qquad A=\operatorname{softmax}_{\mathrm{key}}(S),\qquad O=AV.$$

$D$是Q/K向量宽度；除以$\sqrt D$用于控制点积尺度。$S$是分数，也叫logits；$A$是权重，$O$是输出。设batch有$B$条序列、每条有$L$个位置，Q/K为$[B,L,D]$，则$S,A$为$[B,L,L]$。V若宽度为$D_v$，输出就是$[B,L,D_v]$。

下面直接给三个位置的Q/K/V赋值，观察一个注意力头。代码中的`transpose(-1,-2)`交换最后两个轴；`@`做矩阵乘法。

```python
import math
import torch

torch.set_num_threads(1)
q = torch.tensor([[[1., 0.], [0., 1.], [1., 1.]]], dtype=torch.float64)
k = q.clone()
v = torch.tensor([[[1., 0.], [0., 2.], [3., 3.]]], dtype=torch.float64)
mask = torch.ones(3, 3, dtype=torch.float64).tril()
content_logits = q @ k.transpose(-1, -2) / math.sqrt(2)
masked_logits = content_logits + mask.log()
plain_weights = masked_logits.softmax(dim=-1)
plain_output = plain_weights @ v
print(plain_weights.round(decimals=4).tolist())
print(plain_output.round(decimals=4).tolist())
```

`tril()`保留下三角：第0行只看位置0，第1行可看0和1，第2行可看全部。mask用1表示允许、0表示屏蔽；`log(1)=0`、`log(0)=-inf`，softmax后屏蔽位置权重为0。第一行输出因此就是`[1,0]`。最后一行权重约为`[0.2483,0.2483,0.5035]`，输出是三个value的加权和，约为`[1.7587,2.0070]`。

到这里，计算已经知道向量内容，也知道哪些位置可见。位置编码继续告诉模型“候选内容在什么位置”。例如输入中出现两次同样的词，模型还需要判断要读前一次还是后一次。

## 2. RoPE怎样让点积带上相对位置

最直接的位置编码给每个序号准备一个向量，加到token向量上。RoPE则把位置转换成旋转角度，旋转Q和K，再计算点积。

二维向量$[x,y]$旋转角度$\alpha$后成为：

$$[x\cos\alpha-y\sin\alpha,\;x\sin\alpha+y\cos\alpha].$$

例如把$[1,0]$旋转$\pi/2$弧度，也就是90度，会得到$[0,1]$。对于位置$m$，使用角度$m\omega$，其中$\omega$是这一对通道的频率。不同通道对使用不同频率，可以同时表达不同尺度的位置变化。这里RoPE把通道两两配对，向量宽度取正偶数。

![原课程的RoPE旋转与相对点积图](代码/imgs/rope_1.png)

图中第一式是二维旋转；中间的大矩阵把多组二维旋转放到对角线上；底部说明旋转后点积的关系：

$$\big(R_mq\big)^T\big(R_nk\big)
=q^TR_m^TR_nk=q^TR_{n-m}k.$$

$R_m$表示按位置$m$构造的旋转矩阵，$T$表示转置。query与key都旋转后，共同的绝对位移会抵消，位置项留下带符号的$n-m$。例如$m=2,n=5$与$m=9,n=12$，位置差都为3。

原notebook用两个函数展示这个过程。下面保留它们的完整函数体：第一个建立复数相位表，第二个建立4维例子所用的实数旋转矩阵。

```python
def precompute_freqs_cis(dim: int, end: int, theta: float = 10000.0):
    freqs = 1.0 / (theta ** (torch.arange(0, dim, 2)[: (dim // 2)].float() / dim))
    t = torch.arange(end)
    freqs = torch.outer(t, freqs).float()
    freqs_cis = torch.polar(torch.ones_like(freqs), freqs)
    return freqs_cis

def get_rope_matrix(d, theta):
    """Construct the ROPE rotation matrix."""
    cos_theta = torch.cos(theta)
    sin_theta = torch.sin(theta)
    mat = torch.zeros(d, d)
    mat[0:d//2, 0:d//2] = torch.diag(cos_theta)
    mat[d//2:, d//2:] = torch.diag(cos_theta)
    mat[0:d//2, d//2:] = -torch.diag(sin_theta)
    mat[d//2:, 0:d//2] = torch.diag(sin_theta)
    return mat

phases = precompute_freqs_cis(4, 3)
frequencies = torch.tensor([1., 0.01])
rq = torch.tensor([1., 2., 3., 4.])
rk = torch.tensor([4., 3., 2., 1.])
rm = get_rope_matrix(4, 2 * frequencies)
rn = get_rope_matrix(4, 5 * frequencies)
r_relative = get_rope_matrix(4, 3 * frequencies)
left_score = torch.dot(rm @ rq, rn @ rk)
relative_score = torch.dot(rq, r_relative @ rk)
print(list(phases.shape), phases.dtype)
print(round(left_score.item(), 6), round(relative_score.item(), 6))
```

两个点积都约为1.806731。`dim=4`有两对通道，频率为$[1,0.01]$；`end=3`生成位置0、1、2。`outer`把三个位置分别乘两种频率，角度表为`[[0,0],[1,.01],[2,.02]]`。`polar`把每个角度转成$\cos\alpha+i\sin\alpha$，输出complex64的`[3,2]`表；每个复数保存一对旋转系数。

图中矩阵采用相邻通道配对；原`get_rope_matrix`采用半区配对，4维时配对为`(0,2)`与`(1,3)`。两种布局可通过重排坐标对应，使用时保持向量与旋转矩阵的布局一致。原函数用`torch.zeros`分配CPU float32矩阵，上面的比较也按这个精度进行。

RoPE的位置角度仍由token序号决定。问题“上一句话在哪里”需要结合句子边界；CoPE从这里改变计数单位。

## 3. 从数token到数句子

![CoPE v2第2页Figure1](图片/CoPE_v2_p2_Figure1.png)

来源：[Contextual Position Encoding: Learning to Count What’s Important，v2，第2页Figure 1](https://arxiv.org/abs/2405.18719v2)。图中的上下文是“Alice was tired. She tried reading. A rabbit came”，当前query在最后的`came`。`rabbit`被拆成`rabb`与`-it`两个token。

先看粉色区域：从当前token向左数，位置依次为0、1、2……11。图中的斜线区域画出偏向近期token的注意力示意。

再看黄色区域：Gates一行只在两个句号处写1，其余写0；从右往左累加后，最近这一句的位置都变成0，前一句是1，再前一句是2。现在，query若想读当前句，就可以学习偏向位置0。门值决定了“数的是什么”。

这里用0/1门值展示计数含义。实际CoPE通过sigmoid得到连续门值，训练会调整其取值。

```python
tokens = ["Alice", "was", "tired", ".", "She", "tried",
          "reading", ".", "A", "rabb", "-it", "came"]
sentence_gates = torch.tensor([float(t == ".") for t in tokens])
sentence_positions = sentence_gates.flip(-1).cumsum(-1).flip(-1)
soft_gates = torch.tensor([0., 0.25, 0.5, 0.75])
soft_positions = soft_gates.flip(-1).cumsum(-1).flip(-1)
print(sentence_positions.tolist())
print(soft_positions.tolist())
```

输出为`[2,2,2,2,1,1,1,1,0,0,0,0]`与`[1.5,1.5,1.25,0.75]`。`flip(-1)`先把key顺序翻转，`cumsum`逐项累加，再翻回来，就得到每个位置到最右端的后缀和。

课程的矩阵图也可以按一行一行读：

![原课程的固定距离与CoPE累计位置矩阵](代码/imgs/rel_position_matrix.png)

上半部分第$i$行的固定距离为$i-j$；下半部分同一位置改为$g_{ij}+g_{i,j+1}+\cdots+g_{ii}$。对角线从固定距离的0变成当前token的门值$g_{ii}$；所有门为1时，CoPE位置为$i-j+1$。这个多出的1来自“包含当前项”的约定。

## 4. 门值从哪里来，为什么每个query都不同

![CoPE v2第4页公式3和4](图片/CoPE_v2_p4_公式3和4.png)

来源：[CoPE v2，第4页公式(3)–(4)](https://arxiv.org/abs/2405.18719v2)。这段文字的意思是：先为每对query/key计算一个门，决定这个key在距离计数中贡献多少；再累计当前token与目标token之间的门值。门同时依赖query，所以不同query可以采用不同计数方式。

$$g_{ij}=\sigma(q_i^Tk_j),\qquad p_{ij}=\sum_{u=j}^{i}g_{iu}.$$

$i$是当前query位置，$j$是候选key位置，$u$是累加过程遍历的key位置。$g_{ij}$是一个数，$p_{ij}$是query $i$眼中的key $j$位置。sigmoid函数$\sigma(x)=1/(1+e^{-x})$把有限输入映射到0和1之间：分数0得到0.5，分数越大越接近1。

论文附录的实现先把内容分数除以$\sqrt D$，再加因果mask，再送给sigmoid；其门使用的是**已缩放、已屏蔽的内容分数**。未来位置为$-\infty$，门值为0，后缀和就只累计到当前query。完整门矩阵、位置矩阵的形状均为`[B,Q,K]`；$Q$是query数量、$K$是key数量。

顺序应读成“先mask，再计数”。若把未来位置也加入后缀和，当前query算出的距离就会受到未来内容影响。每个query自己的那一行独立累计，不沿query轴相加。

## 5. 位置是1.25时，怎样查表

普通位置查表用整数编号。CoPE的门有小数，累计位置也会有小数，因此需要在相邻两个整数槽之间插值。

![CoPE v2第4页公式5和6](图片/CoPE_v2_p4_公式5和6.png)

来源：[CoPE v2，第4页公式(5)–(6)](https://arxiv.org/abs/2405.18719v2)。原文为每个整数位置准备可学习向量，再按小数部分混合左右相邻的两个向量。

令$f=\lfloor p\rfloor$为向下取整，$c=\lceil p\rceil$为向上取整，$w=p-f$为小数部分：

$$e[p]=(1-w)e[f]+we[c].$$

取$p=1.25$、$e[1]=[2,0]$、$e[2]=[6,4]$，得到$0.75[2,0]+0.25[6,4]=[3,1]$。若query为$[1,2]$，位置部分给注意力增加的分数就是$[1,2]\cdot[3,1]=5$。

```python
position = torch.tensor(1.25, dtype=torch.float64, requires_grad=True)
position_table = torch.nn.Parameter(torch.tensor(
    [[0., 0.], [2., 0.], [6., 4.], [0., 0.]], dtype=torch.float64))
low = position.floor().long()
high = position.ceil().long()
fraction = position - low
position_vector = ((1 - fraction) * position_table[low]
                   + fraction * position_table[high])
one_query = torch.tensor([1., 2.], dtype=torch.float64)
position_bias = (one_query * position_vector).sum()
position_bias.backward()
print(position_vector.detach().tolist(), position_bias.item())
print(position.grad.item())
```

输出为`[3,1]`、`5.0`与导数`12.0`。`requires_grad=True`让PyTorch记录关于position的计算；`backward()`从最终分数反向求导。尽管整数索引本身不求导，小数权重仍保留梯度。这里的导数为$q^Te[2]-q^Te[1]=14-2=12$。

## 6. 先点积再插值，省去一层向量展开

如果给每对query/key都建立一个长度$D$的位置向量，中间量会成为`[B,Q,K,D]`。利用点积对加法和乘法的线性，可以先给整数位置打分，再对这些标量分数插值。

![CoPE v2第5页公式7至9](图片/CoPE_v2_p5_公式7至9.png)

来源：[CoPE v2，第5页公式(7)–(9)](https://arxiv.org/abs/2405.18719v2)。式(7)先计算$z_i[r]=q_i^Te[r]$，其中$r$遍历整数槽；式(8)用同样的小数权重混合两个分数；式(9)把结果加到原内容分数后做softmax。

上一节的query先和两个整数向量点积，得到2和14，再算$0.75\times2+0.25\times14=5$，与先插向量再点积相同。

实际代码把整数位置表保存为`[1,D,P]`，$P$是表槽数。因此：

```text
query[B,Q,D] @ pos_emb[1,D,P]  → 整数槽分数[B,Q,P]
按floor/ceil位置gather          → 两份[B,Q,K]
按小数部分混合                 → 位置偏置[B,Q,K]
内容分数 + 位置偏置             → softmax权重[B,Q,K]
权重 @ value[B,K,Dv]           → 输出[B,Q,Dv]
```

`gather(-1,index)`沿最后一个轴，按每个位置给出的索引取数。`CoPE.forward`返回的是加到内容分数上的偏置；生成权重和混合V由`SelfAttn.forward`接着完成。内容注意力仍要保存query/key之间的分数矩阵。

## 7. 把完整两个类读一遍

这两个类来自原notebook的Markdown第39格，对应论文第12–13页Appendix B Listing 1。`class CoPE(nn.Module)`表示继承PyTorch模块；`__init__`建立对象，`super().__init__()`先完成父类初始化；`self`保存这个对象的表与配置。调用`module(...)`时，PyTorch进入其`forward`方法。

`nn.parameter.Parameter`把张量登记为可训练参数；`SelfAttn`把CoPE登记为子模块，所以`model.parameters()`也能找到位置表。

```python
from torch import nn

class CoPE(nn.Module):
    def __init__(self, npos_max, head_dim):
        super().__init__()
        self.npos_max = npos_max
        self.pos_emb = nn.parameter.Parameter(torch.zeros(1, head_dim, npos_max))

    def forward(self, query, attn_logits):
        gates = torch.sigmoid(attn_logits)
        pos = gates.flip(-1).cumsum(dim=-1).flip(-1)
        pos = pos.clamp(max=self.npos_max - 1)
        pos_ceil = pos.ceil().long()
        pos_floor = pos.floor().long()
        logits_int = torch.matmul(query, self.pos_emb)
        logits_ceil = logits_int.gather(-1, pos_ceil)
        logits_floor = logits_int.gather(-1, pos_floor)
        w = pos - pos_floor
        return logits_ceil * w + logits_floor * (1 - w)

class SelfAttn(nn.Module):
    def __init__(self, npos_max, head_dim):
        super().__init__()
        self.cope = CoPE(npos_max, head_dim)
        self.head_dim = head_dim

    def forward(self, query, key, val, mask):
        attn_logits = torch.bmm(query, key.transpose(-1, -2))
        attn_logits = attn_logits / math.sqrt(self.head_dim)
        attn_logits += mask.log()
        attn_logits += self.cope(query, attn_logits)
        attn = torch.softmax(attn_logits, dim=-1)
        out = torch.bmm(attn, val)
        return out
```

从上往下对应前面的例子：

| 代码 | 输入→输出 | 作用 |
|---|---|---|
| `sigmoid` | masked logits`[B,Q,K]`→同形门值 | 决定各key的计数贡献 |
| `flip/cumsum/flip` | 门值→同形小数位置 | 逐query从右向左计数 |
| `clamp(max=P-1)` | 小数位置→表范围内位置 | 表槽编号0到P−1，超出时使用末槽 |
| `ceil/floor/long` | 小数位置→int64索引 | 定位插值两侧的整数槽 |
| `query @ pos_emb` | `[B,Q,D] @ [1,D,P]`→`[B,Q,P]` | 给整数位置打分 |
| 两次`gather`和混合 | 整数分数→偏置`[B,Q,K]` | 对应先点积再插值 |
| `softmax`和`bmm` | 合并分数→权重→输出 | 沿key归一化后混合value |

`matmul`允许位置表前导维1向batch广播；`bmm`接收三个轴的batch矩阵，要求batch数量匹配。类的输入是已经算好的Q/K/V；在完整Transformer中，上游投影层负责产生这些向量。

`npos_max`决定位置表容量。比如$D=2,P=4$，位置表有8个参数，最大位置为3；更远的累计位置会合并到末槽。若整行mask都为0，softmax面对全$-\infty$会得到NaN，所以每个query需有至少一个可见key。这里的mask接口使用0/1。

## 8. 零表怎样开始学习

位置表初始全0，因而CoPE偏置也是0。第一次前向恰好等于第1节的普通masked attention。损失仍能对位置表求出梯度，优化器据此修改表；表有不同数值后，小数插值也会把梯度传回门值和Q/K。

下面沿用第1节的三个Q/K/V，固定这些输入，只训练原类的8个位置参数。目标设为全0，用均方误差观察更新过程。`optimizer.zero_grad()`清旧梯度，`backward()`求新梯度，`step()`执行一次Adam更新。

```python
model = SelfAttn(npos_max=4, head_dim=2).double()
initial = model(q, k, v, mask)
torch.testing.assert_close(initial, plain_output, rtol=0, atol=0)
target = torch.zeros_like(initial)
optimizer = torch.optim.Adam(model.parameters(), lr=0.02)
loss_history = []
for step in range(5):
    optimizer.zero_grad()
    prediction = model(q, k, v, mask)
    loss = (prediction - target).square().mean()
    loss_history.append(loss.item())
    loss.backward()
    optimizer.step()
with torch.no_grad():
    final_output = model(q, k, v, mask)
    loss_history.append((final_output - target).square().mean().item())
print(sum(p.numel() for p in model.parameters()))
print([round(x, 6) for x in loss_history])
```

第一行输出8，第二行的误差依次为`[1.670743,1.624484,1.578647,1.533344,1.488692,1.444804]`，包括初始值和每次更新后的值。每个位置的内容分数保持固定，模型通过位置偏置改变可见value的混合比例；第0行只有一个可见key，权重总为1，因此它的输出保持`[1,0]`。

关于梯度，还需留意两个直接影响实现的地方：整数结点处，原代码的ceil与floor相同，这一写法选出的门控导数为0；位置超过表上限时，clamp的饱和区间也会让该位置对门值的梯度为0。分析时把这些点与一般小数位置区分开。

## 9. 论文怎样测试“按内容计数”

![CoPE v2第6页Table2](图片/CoPE_v2_p6_Table2.png)

来源：[CoPE v2，第6页Table 2](https://arxiv.org/abs/2405.18719v2)。表中是测试错误率百分比，越低越好；In-dist表示与训练分布相近的测试集，OOD表示改变了输入分布的测试集。

左半边的**Flip-Flop**可以理解成读写一个记忆位：`w0/w1`写入0或1，`i0/i1`忽略，`r`要求读出最近一次写入的值。OOD中加入更多忽略指令，让相关写入离当前读取更远。主实验使用256维、4头、4层模型，训练10000步。RoPE的In-dist/OOD错误率为1.8%/20.3%，CoPE为表内显示的0.0%/4.9%；OOD减少15.4个百分点。附录C说明使用AdamW、8 GPU、batch16和3个随机种子，细表另列均值与标准差。

右半边的**Selective Copy**要求删去空白token后复制其余内容。例如`DBBCFBFBE`把`B`当空白，输出`DCFFE`。训练与In-dist有256个非空token及256个空白；OOD dense只有128个空白，OOD sparse有512个空白。模型维度64、2层、2头，训练100000步。Absolute PE三列为16.9/25.6/85.2%，RoPE为40.1/100/100%，CoPE为0/0/0%。这组设置检验改变空白密度后，模型是否仍能找到要复制的内容。

两项任务分别比较同一任务架构和训练设置下的位置方法；它们使用的网络大小、步数不同，阅读时按各自任务比较。表中结果来自论文训练，本节的8参数算例用于观察位置表的计算和更新。

## 2. 不带位置的attention究竟少了什么

设输入$X\in\mathbb R^{L\times D_{model}}$，投影矩阵$W_Q,W_K\in\mathbb R^{D_{model}\times D}$、$W_V\in\mathbb R^{D_{model}\times D_v}$。于是Q/K为$[L,D]$，V为$[L,D_v]$。一个head计算：

$$S=\frac{QK^T}{\sqrt D},\quad A=\operatorname{softmax}_{key}(S),\quad O=AV.$$

S是未经归一化的logits/scores，A才是attention weights，二者都是$[L,L]$；输出O是$[L,D_v]$。Q/K最后维必须相同才能内积，V的特征维可以不同。softmax沿每个query对应的key行归一化，不是对整个矩阵求一个总和。

没有位置信息且没有mask时，对所有token施加同一个置换矩阵P，有：

$$\operatorname{Attn}(PQ,PK,PV)=P\operatorname{Attn}(Q,K,V).$$

这叫**置换等变**，不是整个输出与置换前完全相同。它知道哪些内容相似，却没有直接的token顺序坐标。本次真实double张量独立验证该关系。自回归三角mask本身引入可见前缀的顺序约束，因此不能把“无位置的无mask attention”结论不加条件地套到所有decoder上。

RoPE的角度表只由位置与频率决定，不由内容决定；但旋转的Q/K来自内容，最终attention当然仍有语义信息。“RoPE与上下文无关”应限定位置信号的构造，不能说整个注意力与上下文无关。

## 3. 绝对位置：可学习与固定是另一个维度

第5格BERT/GPT风格摘录把位置向量直接加到token embedding。BERT还加token_type embedding；其position_embeddings是可学习表。GPT2风格wte是token表，wpe是position表，可选token_type项。这两段实现都按绝对position ID查向量；后续模型还可以采用RoPE等位置编码。

固定sin/cos也使用绝对位置，只是没有可训练位置参数：

$$PE(t,2r)=\sin(t\omega_r),\quad PE(t,2r+1)=\cos(t\omega_r),\quad
\omega_r=10000^{-2r/D_{model}}.$$

t是序列位置，r是通道对编号，范围$0\le r<D_{model}/2$。相邻sin/cos共享同一个频率；不能把通道i误当序列位置。D_model=4时omega=[1,0.01]：t=0的向量[0,1,0,1]，t=1为[sin1,cos1,sin.01,cos.01]。因为相位差与位移相关，绝对编码也可能让网络利用相对关系；“绝对”不是“不包含任何相对信息”。

第5格是两个不完整模型片段，不具备独立forward上下文；本交付对它们加注释与AST核对，没有假称运行了完整预训练BERT/GPT。

## 4. RoPE为什么从绝对角度得到相对点积

二维旋转矩阵为：

$$R(\alpha)=\begin{bmatrix}\cos\alpha&-\sin\alpha\\\sin\alpha&\cos\alpha\end{bmatrix}.$$

它不改变向量长度，逆矩阵等于转置。给query位置m、key位置n分别旋转：

$$\tilde q_m=R(m\omega)q_m,\quad\tilde k_n=R(n\omega)k_n,$$
$$\tilde q_m^T\tilde k_n=q_m^TR(m\omega)^TR(n\omega)k_n=q_m^TR((n-m)\omega)k_n.$$

只要使用同一组频率与一致的坐标配对，位置项就通过**带符号n-m**进入点积，不是$|n-m|$。共同把两个位置都加c会抵消，但q/k内容仍可能随其真实上下文变化；这里的代数等式是在固定向量下讨论旋转。

在D维中把D/2个二维旋转组成块对角矩阵，频率$\omega_r=\theta^{-2r/D}$。这里D通常是head_dim，不是整个模型hidden_size。非学习的标准RoPE不新增位置训练参数，模型的Q/K投影仍可学习；变体的频率缩放等不能从本例默认theta=10000泛化。

### 相邻配对和半区配对不能直接混用

第20格的R12/R34是完整4×4嵌入矩阵，在(1,2)、(3,4)平面分别旋转，构成相邻配对。两个小2×2矩阵本身不能相乘后就得到4维旋转；应block_diag，或像原例先嵌入4维再相乘。

第23格get_rope_matrix把cos/sin放入四个半区：

$$R_{half}=\begin{bmatrix}\operatorname{diag}(c)&-\operatorname{diag}(s)\\\operatorname{diag}(s)&\operatorname{diag}(c)\end{bmatrix}.$$

这时配对坐标是(0,2)、(1,3)，与前面不同。令P把向量从[x0,x1,x2,x3]改排为[x0,x2,x1,x3]，就有$R_{half}=PR_{adjacent}P^T$。本次按原角pi/6、pi/3真实核对。两种写法通过这个坐标重排对应起来；若只换旋转矩阵不换向量/权重布局，输出会改变。

第21格先检验RR^T=R^TR，这只说明该矩阵满足一种交换关系，不足证明正交。例如diag(2,3)也满足，但RR^T不等于I。原第二个比较与单位阵相同才是当前数值例子的正交检查；它仍不代替一般证明。

### precompute_freqs_cis逐步看

| 变量/API | 含义、dtype与shape |
|---|---|
| dim / end / theta=10000.0 | head维D、位置数量L、基础常数 |
| arange(0,D,2).float()/D | 通道指数[0,2/D,...]，float32[D/2] |
| freqs（第一次） | 倒数角频率omega，float32[D/2] |
| t=arange(end) | 0到L-1，整数[L] |

D=4、L=3得到角度[[0,0],[1,.01],[2,.02]]，复数表第一行全1。freqs_cis不是显式D×D旋转矩阵；把每对实通道视为一个复数后与它相乘才实现旋转。原Markdown9的wq/wk/wv、apply_rotary_emb以及xq_等来自不同步骤，没有完整类上下文，不能整块照抄就宣称运行了Attention。

原get_rope_matrix用torch.zeros(D,D)默认CPU float32。即使输入double角度，结果也是float32；本次明确观测。dim为奇数时precompute可能静默只生成floor(D/2)组，另一矩阵函数可能尺寸错误。调用者应满足偶数维/频率长度契约；本交付保留缺少显式校验的原函数，在验证中记录边界。

尤其D=3、theta只有1个元素时，切片赋值会广播，函数居然返回3×3矩阵而不是报错；实测只有rank2、非正交，不能当合法旋转。角度长度过大才在另一例实际尺寸报错。因此“没有抛异常”远不足证明输入被正确支持。

## 5. CoPE改变的是距离的计数单位

普通token相对距离告诉你“向左几个token”，但句长不固定；“最后一句话”不是一个固定token窗口。CoPE的思路是先决定当前query在计数时要数哪些key，再把这些软计数累计成位置。

论文式(3)、(4)写作：

$$g_{ij}=\sigma(q_i^Tk_j),\quad p_{ij}=\sum_{u=j}^{i}g_{iu}.$$

i是当前query位置，j是被关注的key位置；g为gate，值通常在0与1之间。**不是每个key都有一个与query无关的固定gate**：不同i可以选择不同计数单位，层/head也可不同。若所有有效门为1，则p_ij=i-j+1，含当前项，比常见i-j多1；这只是索引约定差异。

以同一query的一行gate=[0,.25,.5,.75]为例，从右向左和得到position=[1.5,1.5,1.25,.75]。第一个0门不增加距离，两个不同token因此可以共享一个位置。图里只把句号的门设为1，就能让同句token共享“距离当前第几句”的位置；它是理想示意，训练前不会自动出现这样的句号检测器。

实现里的attn_logits已经先做qk/sqrt(D)，再加mask.log，然后sigmoid。因此Listing1门控实际接收**缩放后且已mask的内容分数**；对照公式时，sqrt(D)的缩放已包含在attn_logits中。它没有单独的gate MLP，gate的可学习能力也依靠上游Q/K及训练。

### 为什么flip两次？

~~~python
gates = torch.sigmoid(attn_logits)
pos = gates.flip(-1).cumsum(dim=-1).flip(-1)
~~~

flip(-1)先逆转key方向，cumsum在逆序上从左累加，再翻回来，就得到每个key到最右侧的后缀和。完整形状是[B,Q,K]；cumsum不是在query轴，也不是对batch求和。

自回归mask要**先**作用于logits，使未来key分数为-inf，sigmoid(-inf)=0，后缀和里的未来项才不污染过去位置。代码允许对角线时，求和包括当前token；若改成严格只看过去的mask，位置约定也会变。本次验证完整因果序列与各长度前缀重算输出一致，并检查改动未来Q/K/V不改变过去输出；没有实现或验证CoPE KV cache。

## 6. 小数位置怎样查可训练表

设可训练整数槽表为e[0],...,e[P-1]，每个向量长度D。代码保存为pos_emb[1,D,P]，前导1让不同batch共享参数；一共DP个参数。Parameter(torch.zeros(...))会注册成可训练参数，普通torch.zeros本身不会；它虽不是nn.Embedding对象，却同样可被Module.parameters与optimizer发现。

论文式(5)线性插值：

$$f=\lfloor p\rfloor,\quad c=\lceil p\rceil,\quad w=p-f,\quad
e[p]=(1-w)e[f]+we[c].$$

例如p=1.25，取e1=[2,0]、e2=[6,4]，得到e[p]=.75e1+.25e2=[3,1]。floor/ceil后转long形成不可微整数索引，但小数权重w仍有浮点梯度；因此不能说“一转long整个CoPE就不可训练”。

为避免p超出表范围，代码clamp(max=P-1)。P是表槽数，最大合法索引P-1；论文写整数0到T时，对应P=T+1。表可以小于token长度，但饱和后较远位置会合并到末槽，不能因此宣称无损支持无限上下文。P=1时所有位置相同，位置bias对一个query的所有key是常数，在softmax中抵消，无法区分距离。

### 为什么先点积再插值更省？

若先为每对query/key构造e[p_ij]，会形成[B,Q,K,D]中间量。利用点积线性，先算论文式(7)–(9)：

$$z_i[r]=q_i^Te[r],\qquad
z_i[p_{ij}]=(1-w_{ij})z_i[f_{ij}]+w_{ij}z_i[c_{ij}],$$
$$a_{ij}=\operatorname{softmax}_{j}\left(s_{ij}+z_i[p_{ij}]\right).$$

z_int为[B,Q,P]，两个gather的索引与输出是[B,Q,K]，最后得到的只是**位置logit偏置**，不是attention权重或输出hidden state。上面数值例再取q=[1,2]，先插值得q·[3,1]=5；先算整数点积q·e1=2、q·e2=14，再.75×2+.25×14也等于5。

位置部分不再保存[B,Q,K,D]向量，但内容attention仍有[B,Q,K]矩阵和QK^T乘法。因此这不是线性复杂度attention，也不能仅凭公式就宣称实际峰值显存下降了多少。本次只做前向/梯度等价，没有跑速度或显存benchmark。

## 7. 把两个类从Python读到张量

class CoPE(nn.Module)表示继承PyTorch模块；__init__构造参数，super().__init__先初始化父类才能正常登记子Module/Parameter。self是对象实例，保存表与槽数；调用model(...)经过Module机制进入forward。SelfAttn把CoPE作为子模块，所以其parameters也包含位置表。

| 对象/方法 | 输入、参数与默认值 | 返回/状态 |
|---|---|---|
| precompute_freqs_cis | dim:int、end:int、theta:float=10000.0 | complex64[end,D/2]，不修改模型 |
| get_rope_matrix | d、theta[D/2]，无默认值 | CPU float32[D,D]半区矩阵 |
| CoPE.__init__ | npos_max=P、head_dim=D，均必填 | 注册零表[1,D,P]，DP参数 |
| CoPE.forward | query[B,Q,D]、attn_logits[B,Q,K] | 位置bias[B,Q,K]，不在forward里更新参数 |
| SelfAttn.__init__ | P、D，均必填 | 建立CoPE子模块，保存D |
| SelfAttn.forward | query[B,Q,D]、key[B,K,D]、val[B,K,Dv]、mask可广播至[B,Q,K] | 输出[B,Q,Dv]；QKV投影与output投影均不在类中 |

本次实测B=2、Q=K=4、D=3、Dv=2、P=8。这里CoPE的head_dim可以是奇数3，因为它不做RoPE二维配对；不能把RoPE偶数维约束硬套到CoPE。

~~~text
Q[2,4,3] @ K.transpose[2,3,4]       -> content logits[2,4,4]
/sqrt(3) + log(mask[4,4])           -> masked logits[2,4,4]
sigmoid / 后缀累计 / clamp          -> pos[2,4,4]
Q @ pos_emb[1,3,8]                 -> z_int[2,4,8]
gather(ceil/floor) / 小数插值        -> bias[2,4,4]
softmax(masked logits + bias)      -> A[2,4,4]
A @ V[2,4,2]                      -> O[2,4,2]
~~~

torch.bmm仅接受3维batch矩阵，不像matmul自动广播batch。query乘位置表使用matmul，前导1可广播。transpose(-1,-2)交换key的最后两轴；gather(-1,index)在位置表轴选分数，不是沿head_dim选特征。ceil/floor、long和clamp各自的作用要分开。

该mask接口要求允许=1、屏蔽=0，mask.log才会产生0/-inf；**不要直接传通常的0/-inf加性mask**，否则再次log会产生NaN，转long后成为非法负索引，本次实际RuntimeError。它没有显式验证mask契约。若一整行都屏蔽，最终softmax全-inf得到NaN；调用者要保证每个query有合法key，或另行实现安全的全屏蔽处理。

## 8. CoPE的梯度从哪里来

在非整数p、未饱和区间，插值对位置的导数为：

$$\frac{\partial z[p]}{\partial p}=z[c]-z[f],\quad
\frac{\partial p_{ij}}{\partial g_{iu}}=\mathbf1[j\le u\le i],\quad
\frac{\partial g}{\partial s}=g(1-g).$$

三者连起来，误差可以经过小数权重、累计和、sigmoid回到Q/K。索引本身不用求导。对整数结点，分段线性函数通常没有唯一两侧导数；原代码ceil=floor时两分数相同，会选择0的门控导数。本次用两个sigmoid(0)=.5、后缀和恰为1的构造实际测到0；gradcheck专门避开这些结点与饱和边界，结点处的行为需要单独分析。

零初始化位置表意味着z全0，初始CoPE bias为0，与普通masked attention完全相同。这时**位置支路**对gate的梯度为0，但位置表自身通常有非零梯度；更新表后gate路径开始有非零梯度。SelfAttn的内容qk支路仍会给Q/K梯度，不能说第一步整个attention都不能训练。本次单独核对零表/非零表两种情况。

clamp饱和也会切断该位置对gate的局部梯度；P=1的例子实际为0。解释这类训练行为，比只看一个forward打印值更能判断公式是否真正实现。

## 10. 小张量中的位置与梯度

把CoPE的“先算各位置分数再插值”和“先插值完整向量再点积”并排计算，double精度下前向最大差约1.11e-16；Q、K、V和位置表的梯度最大差不超过4.45e-16。两种写法表达了同一条计算路径。

再固定随机Q/K/V与MSE目标，只训练原类的24个位置参数。用学习率0.02执行5次Adam更新，loss从1.2536735降至1.2374721。误差通过插值权重回到位置表，说明这张表能够跟随目标学习。

这组随机张量用于观察公式和参数更新；运行方法及数值输出见[复现说明](复现/README.md)。
