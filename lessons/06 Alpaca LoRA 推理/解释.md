## 3. 单元 7、10–15：加载和检查

`LlamaForCausalLM` 是含因果 LM 输出头的模型类；`LlamaTokenizer` 是配套分词器；`GenerationConfig` 存生成选项。

`from_pretrained` 是类方法，输入模型标识与选项，返回加载好的对象；可能下载文件并分配 CPU/GPU 内存。`load_in_8bit=True` 是量化加载路线，`device_map='auto'` 是自动设备安排，不同于第 07 讲训练期间的 autocast。

单元 12 的 `named_parameters()` 每项为 `(name,parameter)`，`para[1]` 取得 tensor，`.device` 查看设备，`.dtype` 查看类型。打印编号 i 是 Python 遍历序号，不是模型层 ID。

字幕的双卡均分是讲师机器的观测，不是 `auto` 的固定规则；它可能只放一张卡，也可能按可用资源分布。嵌入、norm 等仍可使用浮点类型，不能把全模型都叫 int8 tensor。

tokenizer 的词表规模与 embedding 第一维匹配；每个 ID 映射到一个隐藏向量。历史打印可见常见第一代 7B 的 H=4096、V=32000，但本次未加载权重测量。

## 4. 单元 18–21：读取已有 adapter【必须会】

`PeftModel.from_pretrained(model,adapter_id)` 将给定基模型作为输入，读取 adapter 配置与参数，构造 PEFT 包装对象。它不同于第 03 讲 `get_peft_model` 创建新的训练适配器，也不是运行新的训练步骤。

单元 21 保存的历史输出明确是：

```text
model_type llama
['q_proj', 'k_proj', 'v_proj', 'o_proj']
```

同一单元打印的库默认 mapping 对 llama 是 q_proj/v_proj。**已有 adapter 自己保存的 target_modules 优先于“如果新建配置时未指定”的默认推断。** 不能据默认映射将本讲已有 adapter 说成只覆盖 Q/V。

`model.peft_config['default']` 取名为 default 的 adapter 配置；default 是键名，不是模型架构。内部 mapping/other 导入是调试用法，其路径会随库版本变化。

在某个 4096→4096 的目标映射上，若 adapter rank=16，A 权重 `[16,4096]`，B `[4096,16]`，激活 `[B,S,4096] → [B,S,16] → [B,S,4096]`。rank 应以实际 adapter 配置为准；这里按字幕/历史结构说明，未读取远程新 revision。

【必须会】已有LoRA参数怎样参与一层前向：对列向量x，

$$y=Wx+\frac{\alpha}{r}BAx.$$

W为基础投影[out,in]，A为[r,in]，B为[out,r]；r是低秩维数，α是缩放参数，x[in]→Ax[r]→BAx[out]，与Wx[out]相加。无bias的例子用于解释；有bias时基础支路还加bias。dropout在训练时作用于adapter输入，推理eval下不随机丢弃。本段B指LoRA矩阵；batch用N标记时，PyTorch行向量激活[N,S,in]对应`x @ A.T @ B.T`，不是把W方向倒过来。

小例子W为2×2单位阵，x=[1,2]，r1/α1，A=[1,0]、B=[2,3]ᵀ：基础结果[1,2]，Ax=1，低秩增量[2,3]，y=[3,5]。真实LLaMA还会在投影后继续attention/MLP，这个两维例子不代表整个模型。源码位置对应固定PEFT的LoraModel目标层替换与Linear.forward，读取参数来自PeftModel.from_pretrained；本次教学r2/α4的scale为2，和老师未锁定adapter配置分开。

## 5. 单元 24：`generate_prompt` 每个分支

这是普通 Python 函数，输入 instruction（预期 str）和可选 input（默认 None），返回一个 str，不修改模型，也不 tokenize。

有 input 的模板先说明“指令和补充上下文”，再写 Instruction、Input、Response 三段；无 input 的模板只含 Instruction、Response。英文引导句要求完成任务，结尾 Response 标记后故意留空，让模型续写。

`f` 三引号字符串保存换行，并把大括号变量插入。换行与分隔标签是模型输入的一部分，不只是页面格式。

原函数判断 `if input`，是 Python 真值判断：None、空字符串走无输入分支；非空字符串走有输入分支。它不是“参数只要传过就使用”。参数名 input 还遮蔽 Python 内置 input 名字，但只在这个函数的局部作用域内。

示意 instruction=`Translate to French`、input=`Hello`，将形成带 Input 的模板；只有 instruction=`Tell a joke` 时形成不带 Input 的模板。验证脚本实际提取原函数并执行这两个分支，而非重写后假称原代码成功。

## 6. 单元 25：生成配置的真实语义

| 选项 | 原值 | 解释 |
|---|---|---|
| temperature | 1.5 | 启用 sampling 时调概率分布 |
| top_p | 0.8 | 启用 nucleus sampling 时限制候选 |
| num_beams | 4 | beam 搜索候选束数 |
| do_sample | 未设置 | GenerationConfig 的常见默认为 False |
| num_return_sequences | 未设置 | 通常默认为 1 |

按该配置的默认行为，num_beams>1 且 do_sample=False 是**确定性 beam search**，temperature/top_p 不能直接解释为已启用随机采样。若要 nucleus sampling，需明确 do_sample=True，并按意图设置 beam 数。[Transformers v4.30 GenerationConfig](https://huggingface.co/docs/transformers/v4.30.0/en/main_classes/text_generation)

4 条 beam 是内部候选，不意味着最终返回 4 个答案。字幕说“生成了三个回复”可能是一个答案中包含三个笑话，不能据此推断 num_return_sequences=3。

### 6.1 两种解码关系【建议会】

Sampling 的概率形式为 $p_i=\exp(z_i/T)/\sum_j\exp(z_j/T)$；z `[B,V]` 为 logits，T 为正标量。较大 T 使分布更平缓，top-p 再筛选候选。此公式在未启用采样时不描述本讲实际 beam 策略。

Beam search 依据序列的累积对数概率扩展候选，可写 $\sum_t\log p(x_t\mid x_{<t})$，并结合停止条件、长度惩罚等配置。beam 宽度增加搜索空间，不保证事实正确。

把上式展开成两步：候选A两步概率0.6和0.5，累积概率0.3、log分数约−1.204；候选B为0.4和0.9，概率0.36、log分数约−1.022。即使B第一步较低，完整候选分数可能更高；真实generate还处理长度惩罚、EOS和其他候选，不是只比较第一个token。t是新增序列位置，x_t是该步ID，概率为标量；模型每步先给logits[B×beam,V]。

【建议会】采样温度的数值例子：logits[0,ln3]在T1时softmax为[0.25,0.75]；T2时为[1/(1+√3),√3/(1+√3)]≈[0.366,0.634]，分布更平。这里只解释temperature的作用，原do_sample=False的beam路径没有使用这条采样关系。

## 7. `inference` 的完整变量路径【必须会】

函数输入 instruction 与 input，默认 input=None；使用外部作用域的 model、tokenizer 和 generation_config，返回默认 None，其主要结果是打印。

| 步骤/变量 | 类型与 shape | 作用 |
|---|---|---|
| prompt | str | 生成模板 |
| inputs | BatchEncoding | 包含 input_ids、attention_mask |
| input_ids | int64 `[1,S]` | 取得 ID 并调用 cuda |
| generation_output | 生成输出对象 | 不只是一个普通 tensor |
| sequences | int64 `[R,S+G]` | R 为实际返回序列数，G≤256 |
| s | int64 `[S+G]` | for 遍历一条序列 |
| output | str | decode 得到含输入前缀的文字 |
| split 后片段 | str | 试图提取 Response 后文字 |

`input_ids.cuda()` 不显式指定设备，使用当前 CUDA 设备；自动分派模型时需要核对入口位置，不能认为任意模型分布都适配。原代码没有传 inputs 的 attention_mask；单条无 padding 输入常可使用推断 mask，但批量 padding 应显式传入对应 mask。

`return_dict_in_generate=True` 要求结构化输出；`output_scores=True` 保留每一步分数，但后续没有使用，可能增加内存。`max_new_tokens=256` 限制新增长度，S+G 才是总长。generate 本身的框架实现还处理 cache、停止条件和搜索策略；不是单纯一次 forward。

本次CPU补充的真实beam数据流是input_ids[1,70]→首次forward的[4,70]→缓存续写的[4,1]，最后sequences[1,96]。被选中序列新增26token，搜索却保存55步scores[4,96]：一个候选可先EOS，搜索仍处理其他候选，所以scores步数不必等于最后返回序列的新增长度。词表96属于教学分词器，不是原7B的32000词表；详见[实际记录](复现/README.md)。

decode 未使用 skip_special_tokens，可能包含特殊标记。`split('### Response:')[1]` 依赖字符串分隔符：若不存在会越界，若输入中也出现该标记可分错位置。

更稳健的后处理思路是按 prompt token 长度取新增 ID，再 decode；这是补充写法，不是原源码：

```python
prompt_length = input_ids.shape[-1]
new_ids = generation_output.sequences[0, prompt_length:]
answer = tokenizer.decode(new_ids, skip_special_tokens=True)
```

这种做法通过 token 边界去掉前缀，无须寻找字符串标签；多返回序列则逐条处理。
