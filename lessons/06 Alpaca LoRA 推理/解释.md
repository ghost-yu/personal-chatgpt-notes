# 第 06 讲：LLaMA 基模型与 Alpaca LoRA 的推理流程

这一讲加载基础模型与已有LoRA参数，接收一条指令，再提取生成的回答。用“把Hello翻译成法语”作为示例任务，依次看各个对象与生成配置。

路径是：准备基础模型和分词器→加载LoRA→拼接prompt→分词编号→逐步生成→编号转文字→提取回答。第2节配LoRA原图，第3节给出原模板及中文含义。

[中文注释Python阅读版](代码/tutorials/06_alpaca_llama_7b_lora_代码注释.py)适合直接看代码；[全部28格说明](代码单元解释.md)可按编号查；[原notebook](代码/tutorials/06_alpaca_llama_7b_lora.ipynb)保留老师原代码和历史输出。后面的折叠区保留旧版技术说明。

## 1. 先分清三份东西：模型、分词器、adapter【必须会】

**基础模型**是一组已训练的参数及其计算结构。参数是模型里用于计算的数字；它们让模型根据前面的文本预测后续内容。**分词器tokenizer**把字符串切成token（文本片段），再查词表，变成整数编号；也负责将编号转回文本。**LoRA adapter**是一小组额外参数，配合基础模型改变其输出倾向。

基础模型、分词器和adapter各自需要对应的文件。只拿adapter，通常无法独立完成语言模型计算，因为它不包含完整基础权重。分词器的编号规则也要匹配：即使两个分词器的词表大小相同，同一个编号也可能表示不同片段。

| 原代码读取对象 | 历史标识 | 本次调用的作用 |
|---|---|---|
| `LlamaForCausalLM` | `decapoda-research/llama-7b-hf` | 读取LLaMA基础结构与已有权重 |
| `LlamaTokenizer` | 同一基础标识 | 读取文本与编号之间的规则 |
| `PeftModel` | `tloen/alpaca-lora-7b` | 在传入的基模型上接入已保存的LoRA配置与权重 |

`from_pretrained`可以理解为“从已经保存的文件构造对象”。名字相同，调用者不同，读取的内容就不同。`LlamaForCausalLM`中的CausalLM表示因果语言模型：利用当前及更早的内容预测后续token。

原单元10与19调用以下加载接口：

```python
model = LlamaForCausalLM.from_pretrained(
    'decapoda-research/llama-7b-hf', load_in_8bit=True, device_map='auto')
model = PeftModel.from_pretrained(model, 'tloen/alpaca-lora-7b')
```

`load_in_8bit=True` 量化部分基础权重；`device_map='auto'` 根据可用资源安排模型模块的位置，device可为CPU或具体GPU。课程历史输出展示了老师机器上的双卡分配情况。

第03讲的 `get_peft_model` 创建适配参数，准备训练；这里的 `PeftModel.from_pretrained` 从文件读取已保存的适配参数，供推理使用。

## 2. 看原图：推理时LoRA也必须参与计算【必须会】

![LoRA论文原图：基础分支与低秩分支共同产生输出](图片/LoRA原论文_Figure1_双分支.png)

来源：[LoRA arXiv:2106.09685v2，PDF第1页Figure1](https://arxiv.org/pdf/2106.09685v2)。先看adapter加载后参与哪一步计算。

从下往上，x是某个投影层收到的d维向量。左路经预训练权重W，右路经A缩窄到r维，再经B恢复输出宽度；顶部将两路结果相加得到h。A/B是保存两次变换参数的矩阵。训练LoRA时冻结W、更新A/B；推理时直接使用两路已有参数。

图中 `W∈R^{d×d}` 表示d行d列的实数矩阵。`B=0` 和 `A=N(0,σ²)` 描述初始化：B全零，A按均值0、方差σ²的正态分布随机取值。加载训练好的adapter时，使用文件中保存的A/B数值。

对列向量，忽略偏置并写出实现里的缩放：

$$y=W_0x+\frac{\alpha}{r}BAx.$$

W₀是基础权重，A/B是LoRA小矩阵，r是中间宽度，α是配置的缩放参数。先算Ax，再算B(Ax)，乘α/r，最后与W₀x相加。比如W₀为2×2单位矩阵，x=[1,2]，A=[1,0]，B=[[2],[3]]，α=r=1：基输出[1,2]，右路得到[2,3]，相加为[3,5]。这只是两维算例，不是整个LLaMA。

PyTorch参数存为`[输出宽度,输入宽度]`，若某投影4096→4096、r=16，则A是[16,4096]，B是[4096,16]；一个批次的激活从`[N,S,4096]→[N,S,16]→[N,S,4096]`。N为批内文本数，S为token位置数；shape就是各维长度，B在这里指LoRA矩阵，不是batch。

原单元21的历史输出显示目标为 `q_proj/k_proj/v_proj/o_proj`；llama的新建默认映射是q/v。加载已有adapter时，以它保存的目标层、r和alpha配置为准。

## 3. 用模板组织指令和输入【必须会】

Prompt是模型接下来要续写的整段前缀。这里既要告诉它任务“翻译成法语”，又要给待处理文本“Hello”。原模板用三个标记分清它们：

| 标记 | 中文含义 | 这一例填入 |
|---|---|---|
| `### Instruction:` | 要完成的指令 | `Translate to French` |
| `### Input:` | 补充输入或上下文 | `Hello` |
| `### Response:` | 回答从这里开始 | 留空，等待续写 |

有input时，模板说明的中文意思是：“下面是一条描述任务的指令，以及提供进一步上下文的输入。请给出恰当完成请求的回答。”无input时，意思是：“下面是一条描述任务的指令。请给出恰当完成请求的回答。”代码按原英文模板拼接文本。

`###`、换行和开头说明共同构成prompt。沿用训练时的格式，有助于模型识别指令、补充输入和回答的位置。

下面保留原单元24的完整函数，后面加两次教学调用：

```python
def generate_prompt(instruction, input=None):
    if input:
        return f"""Below is an instruction that describes a task, paired with an input that provides further context. Write a response that appropriately completes the request.

### Instruction:
{instruction}

### Input:
{input}

### Response:"""
    else:
        return f"""Below is an instruction that describes a task. Write a response that appropriately completes the request.

### Instruction:
{instruction}

### Response:"""

prompt = generate_prompt('Translate to French', 'Hello')
print(prompt)
no_context = generate_prompt('Tell a joke')
assert '### Input:' in prompt
assert '### Input:' not in no_context
assert generate_prompt('Tell a joke', '') == no_context
```

`def`定义函数；`instruction`和`input`是形参，`input=None`表示没提供第二个参数时用None。None是“没有值”的Python对象，不是字符串`'None'`。`if input`判断真值：非空字符串走第一支，None或空字符串走第二支。它不是“只要传过第二个参数就有Input段”。

`f`开头的三引号字符串保留换行，并将 `{instruction}`、`{input}` 替换为变量内容。`return` 返回拼好的字符串。局部参数名input在函数内遮蔽了Python内置同名函数。

第一条调用得到的prompt中，Instruction下为Translate to French，Input下为Hello，文本在Response冒号处结束，等待模型续写。`Tell a joke`采用无Input段的分支；空字符串与省略input时结果相同。

## 4. 从prompt到下一token的分数【必须会】

原函数先执行`tokenizer(prompt, return_tensors='pt')`。字符串是Python的str；分词器返回类似字典的BatchEncoding，包含`input_ids`和通常的`attention_mask`。`return_tensors='pt'`要求返回PyTorch张量，而不是普通编号列表；张量在这里可以理解为装数字的多维数组。

假设完整prompt被切成S个token，单条编号的shape为 `[1,S]`，通常用int64保存。mask同形状，标记真实输入和补齐位置。S由完整模板和分词规则决定。

模型先按编号查embedding表，变成`[1,S,H]`隐藏向量；H是每个位置的向量宽度。经过注意力、前馈层和LoRA投影后，输出头给每个位置的词表候选打分，称为logits，shape为`[1,S,V]`；V是词表大小。

续写时主要读取最后输入位置的候选分数，shape为 `[1,V]`。例如分数为0和ln3时，softmax给出概率 `[0.25,0.75]`。选出一个token，将它接回前缀，再计算下一步。

旧7B配置的结构宽度常见为H=4096、词表V=32000。下面用较小尺寸观察相同的接口与shape变化。

## 5. Beam search和采样分别怎么选？【必须会】

**贪心**每一步取当前分数最高的候选。**Beam search（束搜索）**保留若干条候选前缀，继续扩展并比较序列分数。**采样**则按候选概率随机选择，可能让同一输入有不同输出。

两步等长例子：A路径概率为0.6×0.5=0.3，B路径为0.4×0.9=0.36。若第一步只保留A，就会错过整体概率更高的B。Beam search保留多条前缀，按序列分数继续筛选。

数学上常用对数把连乘变成相加：

$$\operatorname{score}(x_1,\ldots,x_G)=\sum_{t=1}^{G}\log p(x_t\mid\text{prompt},x_{<t}).$$

x_t是第t个新增token，G是新增长度；竖线表示“根据给定前缀计算概率”。A的对数分数约−1.204，B约−1.022，后者更高。真实生成还处理长度惩罚、结束符和停止规则，这个等长例子只说明累计路径分数。

原配置为：

| 参数 | 值 | 本例真正意味着什么 |
|---|---:|---|
| `num_beams` | 4 | 内部保留4条候选的束搜索宽度 |
| `do_sample` | 未传，默认False | 没有启用随机采样 |
| `num_return_sequences` | 未传，默认1 | 最终每条输入默认返回1条序列 |
| `temperature` | 1.5 | 采样时可调分布；本配置不能据此声称已随机采样 |
| `top_p` | 0.8 | 采样时的候选筛选阈值；不会自行开启采样 |

这些参数的含义参照[Transformers v4.30.0生成文档](https://huggingface.co/docs/transformers/v4.30.0/en/main_classes/text_generation)。开启采样时，正温度T用z/T调整分数，top-p保留累计概率达到阈值的一组候选。本配置采用4beam搜索，最终默认返回1条序列。

## 6. 一个小型LLaMA，实看输入和输出边界【建议会】

用一个随机1层、H=8、词表8的CPU LLaMA观察 `generate`：输入多少编号、内部保留多少候选、最终返回多长。这个算例只创建基础模型，adapter保存加载的例子见文末复现记录。

```python
import torch
from transformers import LlamaConfig, LlamaForCausalLM

torch.manual_seed(6)
torch.set_num_threads(2)
config = LlamaConfig(vocab_size=8, hidden_size=8, intermediate_size=16,
                     num_hidden_layers=1, num_attention_heads=2,
                     num_key_value_heads=2, max_position_embeddings=32,
                     bos_token_id=1, eos_token_id=None, pad_token_id=0)
tiny = LlamaForCausalLM(config).eval()        # 随机建模，不下载权重
input_ids = torch.tensor([[1, 3, 4]])        # 教学编号，不是Hello的真实分词
with torch.no_grad():
    result = tiny.generate(input_ids=input_ids,
                           attention_mask=torch.ones_like(input_ids),
                           num_beams=4, do_sample=False, max_new_tokens=3,
                           return_dict_in_generate=True, output_scores=True)
prompt_length = input_ids.shape[-1]
new_ids = result.sequences[0, prompt_length:]
print('输入shape:', list(input_ids.shape))
print('返回shape:', list(result.sequences.shape))
print('新增编号数:', new_ids.numel())
print('每步分数shape:', [list(scores.shape) for scores in result.scores])
assert torch.equal(result.sequences[:, :prompt_length], input_ids)
assert result.sequences.shape == (1, 6)
```

`LlamaConfig`规定尺寸，`LlamaForCausalLM(config)`随机创建模型；它与`from_pretrained`读取已有权重不同。`.eval()`切换评估模式以关闭训练随机操作；`with torch.no_grad()`让这个区域不记录用于反向求导的计算过程。两者作用不同，推理时经常配合使用。

`ones_like(input_ids)` 创建同形状全1mask。例子设置 `eos_token_id=None`，固定观察3个生成步骤；`bos_token_id`、`pad_token_id` 指定起始和补齐标记。位置范围由 `max_position_embeddings` 配置，这里共用6个位置。

真实运行观察：输入[1,3]，返回[1,6]，新增3个编号；每一步分数都是[4,8]，即4条beam各有8个词表候选。返回却只有1行，因为默认返回1条序列。输出的前3个编号与输入逐个相同，证明`sequences`包含prompt，不仅是新增回答。

`shape[-1]` 读取最后一维长度；`sequences[0,prompt_length:]` 从第0行的输入末尾开始切片，得到新增ID。`.numel()` 统计元素数，`assert` 核对条件。

## 7. 原inference函数逐步做了什么？【必须会】

原单元25定义`inference(instruction,input=None)`，使用外面的model、tokenizer与generation_config。它主要打印结果，**没有return回答字符串，正常返回None**；单独定义函数也不会自动执行推理。

| 原语句/变量 | 类型、shape或结果 | 在这条路径中的职责 |
|---|---|---|
| `generate_prompt(...)` → prompt | str | 拼指令模板 |
| `tokenizer(...,return_tensors='pt')` → inputs | 包含张量的BatchEncoding | 分词并查编号 |
| `inputs['input_ids'].cuda()` | int64 `[1,S]` | 把编号搬到当前CUDA设备；不会改编号含义 |
| `model.generate(...)` | 结构化生成对象 | 按配置逐步搜索后续token |
| `generation_output.sequences` | 通常`[1,S+G]` | 最终序列，含输入前缀 |
| `tokenizer.decode(s)` | str | 编号还原成文本 |
| `split(...)[1].strip()` | str | 按标签尝试去掉输入，去首尾空白 |
| `print('Response:',...)` | 打印文本，函数默认返回None | 向读者展示 |

`.cuda()` 把编号放到当前GPU，运行时需与模型输入层的设备匹配。原函数只传入input_ids；扩展到有padding的批量输入时，应同时传入attention_mask。

`max_new_tokens=256`是新增token上限，包含前缀的总长是S+G，G≤256；它不是256个英文词或汉字。`return_dict_in_generate=True`让返回值带有sequences等字段；`output_scores=True`额外保留搜索步骤分数，原代码随后没有用到，可能增加内存。

原后处理`output.split('### Response:')[1]`把解码文本按标记拆成列表，再取第二段。`strip()`仅去掉该段前后空白。若指令本身包含同一标记，会拆错位置；若不存在标记，取[1]会越界。默认decode也可能保留特殊标记。

更稳妥的补充思路是先按输入token长度取新增ID，再执行`tokenizer.decode(new_ids,skip_special_tokens=True)`；上面的小例子已经验证前缀切片。它不依赖文本里恰好出现几次Response标签，仍需按实际返回序列逐条处理。

单元26的 `inference(input('Instruction: '))` 等待键盘输入，再将字符串交给inference。这里的input是Python内置交互函数。最后27格为空。

## 3. 单元 7、10–15：加载和检查

`LlamaForCausalLM` 是含因果 LM 输出头的模型类；`LlamaTokenizer` 是配套分词器；`GenerationConfig` 存生成选项。

`from_pretrained` 是类方法，输入模型标识与选项，返回加载好的对象；可能下载文件并分配 CPU/GPU 内存。`load_in_8bit=True` 是量化加载路线，`device_map='auto'` 是自动设备安排，不同于第 07 讲训练期间的 autocast。

单元 12 的 `named_parameters()` 每项为 `(name,parameter)`，`para[1]` 取得 tensor，`.device` 查看设备，`.dtype` 查看类型。打印编号 i 是 Python 遍历序号，不是模型层 ID。

字幕的双卡均分是讲师机器的观测，不是 `auto` 的固定规则；它可能只放一张卡，也可能按可用资源分布。嵌入、norm 等仍可使用浮点类型，不能把全模型都叫 int8 tensor。

tokenizer 的词表规模与 embedding 第一维匹配；每个 ID 映射到一个隐藏向量。历史打印可见常见第一代 7B 的 H=4096、V=32000，但本次未加载权重测量。

## 4. 单元 18–21：读取已有 adapter【必须会】

`PeftModel.from_pretrained(model,adapter_id)` 将给定基模型作为输入，读取 adapter 配置与参数，构造 PEFT 包装对象。它不同于第 03 讲 `get_peft_model` 创建新的训练适配器，也不是运行新的训练步骤。

单元 21 保存的历史输出明确是：

```text
model_type llama
['q_proj', 'k_proj', 'v_proj', 'o_proj']
```

同一单元打印的库默认 mapping 对 llama 是 q_proj/v_proj。**已有 adapter 自己保存的 target_modules 优先于“如果新建配置时未指定”的默认推断。** 不能据默认映射将本讲已有 adapter 说成只覆盖 Q/V。

`model.peft_config['default']` 取名为 default 的 adapter 配置；default 是键名，不是模型架构。内部 mapping/other 导入是调试用法，其路径会随库版本变化。

在某个 4096→4096 的目标映射上，若 adapter rank=16，A 权重 `[16,4096]`，B `[4096,16]`，激活 `[B,S,4096] → [B,S,16] → [B,S,4096]`。rank 应以实际 adapter 配置为准；这里按字幕/历史结构说明，未读取远程新 revision。

【必须会】已有LoRA参数怎样参与一层前向：对列向量x，

$$y=Wx+\frac{\alpha}{r}BAx.$$

W为基础投影[out,in]，A为[r,in]，B为[out,r]；r是低秩维数，α是缩放参数，x[in]→Ax[r]→BAx[out]，与Wx[out]相加。无bias的例子用于解释；有bias时基础支路还加bias。dropout在训练时作用于adapter输入，推理eval下不随机丢弃。本段B指LoRA矩阵；batch用N标记时，PyTorch行向量激活[N,S,in]对应`x @ A.T @ B.T`，不是把W方向倒过来。

小例子W为2×2单位阵，x=[1,2]，r1/α1，A=[1,0]、B=[2,3]ᵀ：基础结果[1,2]，Ax=1，低秩增量[2,3]，y=[3,5]。真实LLaMA还会在投影后继续attention/MLP，这个两维例子不代表整个模型。源码位置对应固定PEFT的LoraModel目标层替换与Linear.forward，读取参数来自PeftModel.from_pretrained；本次教学r2/α4的scale为2，和老师未锁定adapter配置分开。

## 5. 单元 24：`generate_prompt` 每个分支

这是普通 Python 函数，输入 instruction（预期 str）和可选 input（默认 None），返回一个 str，不修改模型，也不 tokenize。

有 input 的模板先说明“指令和补充上下文”，再写 Instruction、Input、Response 三段；无 input 的模板只含 Instruction、Response。英文引导句要求完成任务，结尾 Response 标记后故意留空，让模型续写。

`f` 三引号字符串保存换行，并把大括号变量插入。换行与分隔标签是模型输入的一部分，不只是页面格式。

原函数判断 `if input`，是 Python 真值判断：None、空字符串走无输入分支；非空字符串走有输入分支。它不是“参数只要传过就使用”。参数名 input 还遮蔽 Python 内置 input 名字，但只在这个函数的局部作用域内。

示意 instruction=`Translate to French`、input=`Hello`，将形成带 Input 的模板；只有 instruction=`Tell a joke` 时形成不带 Input 的模板。验证脚本实际提取原函数并执行这两个分支，而非重写后假称原代码成功。

## 6. 单元 25：生成配置的真实语义

| 选项 | 原值 | 解释 |
|---|---|---|
| temperature | 1.5 | 启用 sampling 时调概率分布 |
| top_p | 0.8 | 启用 nucleus sampling 时限制候选 |
| num_beams | 4 | beam 搜索候选束数 |
| do_sample | 未设置 | GenerationConfig 的常见默认为 False |
| num_return_sequences | 未设置 | 通常默认为 1 |

按该配置的默认行为，num_beams>1 且 do_sample=False 是**确定性 beam search**，temperature/top_p 不能直接解释为已启用随机采样。若要 nucleus sampling，需明确 do_sample=True，并按意图设置 beam 数。[Transformers v4.30 GenerationConfig](https://huggingface.co/docs/transformers/v4.30.0/en/main_classes/text_generation)

4 条 beam 是内部候选，不意味着最终返回 4 个答案。字幕说“生成了三个回复”可能是一个答案中包含三个笑话，不能据此推断 num_return_sequences=3。

### 6.1 两种解码关系【建议会】

Sampling 的概率形式为 $p_i=\exp(z_i/T)/\sum_j\exp(z_j/T)$；z `[B,V]` 为 logits，T 为正标量。较大 T 使分布更平缓，top-p 再筛选候选。此公式在未启用采样时不描述本讲实际 beam 策略。

Beam search 依据序列的累积对数概率扩展候选，可写 $\sum_t\log p(x_t\mid x_{<t})$，并结合停止条件、长度惩罚等配置。beam 宽度增加搜索空间，不保证事实正确。

把上式展开成两步：候选A两步概率0.6和0.5，累积概率0.3、log分数约−1.204；候选B为0.4和0.9，概率0.36、log分数约−1.022。即使B第一步较低，完整候选分数可能更高；真实generate还处理长度惩罚、EOS和其他候选，不是只比较第一个token。t是新增序列位置，x_t是该步ID，概率为标量；模型每步先给logits[B×beam,V]。

【建议会】采样温度的数值例子：logits[0,ln3]在T1时softmax为[0.25,0.75]；T2时为[1/(1+√3),√3/(1+√3)]≈[0.366,0.634]，分布更平。这里只解释temperature的作用，原do_sample=False的beam路径没有使用这条采样关系。

## 7. `inference` 的完整变量路径【必须会】

函数输入 instruction 与 input，默认 input=None；使用外部作用域的 model、tokenizer 和 generation_config，返回默认 None，其主要结果是打印。

| 步骤/变量 | 类型与 shape | 作用 |
|---|---|---|
| prompt | str | 生成模板 |
| inputs | BatchEncoding | 包含 input_ids、attention_mask |
| input_ids | int64 `[1,S]` | 取得 ID 并调用 cuda |
| generation_output | 生成输出对象 | 不只是一个普通 tensor |
| sequences | int64 `[R,S+G]` | R 为实际返回序列数，G≤256 |
| s | int64 `[S+G]` | for 遍历一条序列 |
| output | str | decode 得到含输入前缀的文字 |
| split 后片段 | str | 试图提取 Response 后文字 |

`input_ids.cuda()` 不显式指定设备，使用当前 CUDA 设备；自动分派模型时需要核对入口位置，不能认为任意模型分布都适配。原代码没有传 inputs 的 attention_mask；单条无 padding 输入常可使用推断 mask，但批量 padding 应显式传入对应 mask。

`return_dict_in_generate=True` 要求结构化输出；`output_scores=True` 保留每一步分数，但后续没有使用，可能增加内存。`max_new_tokens=256` 限制新增长度，S+G 才是总长。generate 本身的框架实现还处理 cache、停止条件和搜索策略；不是单纯一次 forward。

此前CPU补充的真实beam数据流是input_ids[1,70]→首次forward的[4,70]→缓存续写的[4,1]，最后sequences[1,96]。被选中序列新增26token，搜索却保存55步scores[4,96]：一个候选可先EOS，搜索仍处理其他候选，所以scores步数不必等于最后返回序列的新增长度。词表96属于教学分词器，不是原7B的32000词表；详见[实际记录](复现/README.md)。

decode 未使用 skip_special_tokens，可能包含特殊标记。`split('### Response:')[1]` 依赖字符串分隔符：若不存在会越界，若输入中也出现该标记可分错位置。

更稳健的后处理思路是按 prompt token 长度取新增 ID，再 decode；这是补充写法，不是原源码：

```python
prompt_length = input_ids.shape[-1]
new_ids = generation_output.sequences[0, prompt_length:]
answer = tokenizer.decode(new_ids, skip_special_tokens=True)
```

这种做法通过 token 边界去掉前缀，无须寻找字符串标签；多返回序列则逐条处理。
