## 2. 冻结权重与训练准备（单元 15–17）

核心代码：

```python
for i, param in enumerate(model.parameters()):
    param.requires_grad = False
    if param.ndim == 1:
        param.data = param.data.to(torch.float32)
```

`model.parameters()` 遍历 Parameter；`enumerate` 同时提供编号。`requires_grad=False` 不为原权重累积训练梯度；不代表前向跳过，也不代表所有反向都不需要通过这一层。

`ndim==1` 选中一维参数，如部分 norm 权重、偏置；它不是“所有小参数”的严谨判据。转换 float32 旨在提高这些数值计算的稳定性，shape 不变。`.data` 直接访问底层数据是这份历史代码的做法，现代修改应考虑无梯度上下文等方式。

`gradient_checkpointing_enable()` 用反向时重算部分激活减少保存量，以额外计算换显存。它不是“保存 checkpoint 到硬盘”。

**`enable_input_require_grads()` 使输入 embedding 的输出激活能参与梯度链，不等于解冻 embedding 权重。** 原权重之前已经冻结，保持不更新；字幕说法应据代码和方法实现纠正。其目的与冻结模型中梯度检查点的使用有关。[Transformers v4.30 实现](https://github.com/huggingface/transformers/blob/v4.30.0/src/transformers/modeling_utils.py)

`CastOutputToFloat` 继承 `nn.Sequential`。`class` 定义类型，`self` 指实例，`super().forward(x)` 调父类执行包装的 lm_head，再 `.to(float32)` 转输出类型。把 `model.lm_head` 赋为包装对象会改变模块结构；输入 `[B,S,H]`，输出 `[B,S,V]`，转 dtype 不改变 shape。

掌握等级：**【必须会】冻结权重与激活梯度区别；【建议会】checkpointing、继承、输出 cast。**

## 3. LoRA 配置与参数统计（单元 19–22）

`print_trainable_parameters(model)` 是普通函数：遍历 `named_parameters()`，用 `numel()` 累计元素数；仅 `requires_grad=True` 计为可训练；打印百分比，默认返回 None，不修改模型。

| 配置项 | 原值 | 含义 |
|---|---|---|
| r | 16 | 瓶颈维度 |
| lora_alpha | 32 | 标准缩放分子，实际 scale=32/16=2 |
| lora_dropout | 0.05 | LoRA 分支训练时随机屏蔽输入的比例 |
| bias | none | 不额外训练偏置 |
| task_type | CAUSAL_LM | 选择因果 LM 的 PEFT 外层接口 |
| target_modules | 未显式给出 | 由模型类型映射推断；BLOOM 通常为 query_key_value |

注释中的 q_proj/v_proj 没有执行，也不应拿来作为 BLOOM 的实际目标层。`get_peft_model(model,config)` 会包装模型并替换目标子模块，返回 PEFT 模型；旧模型对象内部也会被修改，不是深拷贝一份完全独立网络。

对每层融合 QKV：k=4096、d=12288、r=16，LoRA 参数为：

$$r(k+d)=16(4096+12288)=262144.$$

若目标覆盖 30 层，则总数为 7864320。这是按目标层与维度的推导；是否真实完全相同还须核对实际注入模块、共享参数与配置。字幕约称七百多万、千分之一，不能将口述近似作为测量值。

基权重在 PyTorch 保存 `[12288,4096]`；A `[16,4096]`；B `[12288,16]`。激活流 `[B,S,4096] → [B,S,16] → [B,S,12288]`，与原 QKV 输出相加。详细注入源码在第 04 讲。

## 5. `merge` 与 tokenize（单元 33–39）

`merge(row)` 输入一条记录字典，添加 `prediction` 字段并返回该字典。名字不是预测函数，它只是把训练文本组织为“名言 + 分隔符 + 标签列表字符串”。

示意：quote 为 `Be yourself.`，tags 为 `['life']`，结果是 `Be yourself. ->: ['life']`。作者字段没拼进去。`Dataset.map` 返回转换后的 Dataset，再赋回 train split；不要把它当成遍历 DataLoader。

`tokenizer(list_of_text)` 默认返回由列表构成的 BatchEncoding，还没成为 GPU tensor。单元 38 使用 `batched=True`，因此 lambda 的 samples 是批次字典；`samples['prediction']` 是字符串列表，分词器返回 input_ids 与 attention_mask。lambda 是匿名函数，与写一个命名函数等价。

未设置 padding/truncation，故各条 ID 长度可不同，后面 collator 动态补齐。没有长度上限也可能出现过长样本；不能默认每条都满足模型容量。

```text
row: dict，quote=str，tags=list[str]
→ prediction: str
→ tokenizer: input_ids=list[int]，attention_mask=list[int]
→ collator: int64 tensors [B,S_max_in_batch]
```

## 6. labels 从哪里来？（单元 41–42）【必须会】

`DataCollatorForLanguageModeling(tokenizer,mlm=False)` 接收样本列表，动态 padding，构造 labels；因果 LM 路线通常复制 input_ids，并将 padding 目标设为 -100。-100 是 CrossEntropy 的忽略标记，不是词表 ID。

模型内部再做下一 token 位移：

```text
input_ids = [a,b,c,d]
参与 loss 的预测位置 = [a 后,b 后,c 后]
对应目标             = [b,c,d]
```

不是让位置 a 预测 a。BLOOM forward 的 logits 通常是 `[B,S,V]`，shift 后 `[B,S-1,V]` 与 `[B,S-1]` 的目标配对。[BLOOM v4.30 源码](https://github.com/huggingface/transformers/blob/v4.30.0/src/transformers/models/bloom/modeling_bloom.py)、[collator 源码](https://github.com/huggingface/transformers/blob/v4.30.0/src/transformers/data/data_collator.py)

$$\mathcal L=-\frac1{N_{\mathrm{valid}}}\sum_{b,t\in\mathrm{valid}}\log p_\theta(x_{b,t+1}\mid x_{b,\le t}).$$

b 是 batch 行号，t 是可预测位置，valid 排除忽略目标，N_valid 为有效 token 数。单个目标概率 0.5 的损失为约 0.693。代码冻结主模型，theta 中被更新的是 adapter。

**这份配置通常对名言、分隔符和标签等整段非 padding 文本计算 loss，不只标签部分。** 若只训练回答，需要显式目标 mask。字幕称为多分类任务，但实现是生成标签文本，没有独立固定类别的分类 head，也没直接计算多标签分类指标。

## 7. Trainer 参数与一次训练更新

| 参数 | 原值 | 具体含义 |
|---|---|---|
| per_device_train_batch_size | 4 | 每设备每微批样本数 |
| gradient_accumulation_steps | 4 | 累积 4 个微批后进行一次优化更新 |
| warmup_steps | 100 | 前 100 个优化 step 的学习率预热 |
| max_steps | 200 | 优化更新上限，不是只读取 200 个样本 |
| learning_rate | 2e-4 | 优化器学习率 |
| fp16 | True | 混合精度训练设置；不是所有参数强制 FP16 |
| logging_steps | 1 | 每个优化 step 记录 |
| output_dir | outputs | 本地训练输出位置 |

单设备完整累积周期的有效 batch 为 4×4=16；真正数据并行的 world size 为 D 时可写 4×4×D。**device_map 自动把模型分布到几张卡，不等于 D 个数据并行副本**，不能直接乘卡数。

`Trainer` 保存模型、数据集、训练参数和 collator；`train()` 内部组织微批、forward、loss、backward、累积、更新与日志。`model.config.use_cache=False` 禁用训练中的生成缓存以配合 checkpointing，区别于关掉所有内存优化。

训练前两因子初始化，使增量通常为零；训练后 A/B 改变，基权重保持冻结。原 notebook 没有显式 `save_pretrained()` 的 adapter 导出流程，不应把会打印结构当成已经完成可部署保存。

## 8. 推理两条示例（单元 44–46）

文本末尾留出分隔符，让模型接着输出标签。`return_tensors='pt'` 才创建 `[1,S]` 的整数 tensor；`**batch` 把 input_ids、attention_mask 展开传给 generate。输出通常 `[1,S+G]`，decode 之后包含输入前缀。`max_new_tokens=50` 约束新增 token，不是总文本长度。

原 batch 默认在 CPU，模型可能在 CUDA；`autocast` 不会自动搬运输入。运行时需要核对入口设备/dispatch hook，不能认为包一个 autocast 就解决设备不匹配。原代码也没有显式 eval 和 inference_mode，阅读时应区分训练/评估模式与梯度关闭。

第二例只是另一个文本，不是独立验证集。字幕承认第一例生成不理想，第二例也有问题；loss 降低不等于标签任务成功。不能把两个例子转成准确率或泛化结论。
