    # 下一次 tokens: [8, 9)

## 原单元 14（markdown）

区分返回控制（logprobs/echo）和选词控制（temperature/top_p）。改变echo不改变同一随机种子下的已生成ID，只改变最后切片；logprobs理论上是概率报告，但固定旧版存在记录顺序缺陷，见本讲实测。

## 原单元 15（markdown）

温度公式为p_i(T)=exp(z_i/T)/sum_j exp(z_j/T)，z_i是当前最后位置第i个词表logit，T>0，沿词表归一化。正温度改变分布尖锐度，理论上不改变最大logit索引；熵在非退化例子中随T增加。T=0不能直接代入除法，代码走argmax；负温度也落入else，不做负T softmax。

top_p是在温度softmax之后按概率降序保留动态候选集合、重归一化再采样，不是固定top_k。输出token_logprobs的目标是原模型的log概率，不能直接等同于温度/核截断后采样分布概率；旧版把尚为PAD的新增target先送入CE，实际新增返回-0，不能当真实概率。

## 原单元 16（markdown）

if temperature>0时，logits[:,-1]从[B,S,V]取最后位置得到[B,V]；除标量温度，softmax(dim=-1)沿词表得到概率，sample_top_p返回int64[B,1]。else下torch.argmax(...,dim=-1)返回[B]，所以完整generate随后reshape(-1)统一为[B]。

sample_top_p先sort得到概率与原词表索引，cumsum得到前缀和，用(cumsum-current_prob)>p遮掉候选，原地重归一化，multinomial实际采样，再gather映射回原token ID。使用的是“当前候选之前的累计质量”，因此保留跨过阈值的那一项，恰好等于阈值时也继续保留下一项。它未主动校验p范围；负p可能导致全零/NaN错误。原片段不包含提示词保护、cache更新或停止逻辑，完整流程见官方方法注释。

```python
# 正温度才softmax采样；0或负值走greedy。
if temperature > 0:
    # temperature 与 top_p 组合使用
    # 取最后位置词表分布[B,V]，温度缩放后归一化。
    probs = torch.softmax(logits[:, -1] / temperature, dim=-1)
    # 真实核采样，返回词表ID[B,1]。
    next_token = sample_top_p(probs, top_p)
else:
    # greedy直接选最大logit，[B]；不使用top_p。
    next_token = torch.argmax(logits[:, -1], dim=-1)
```
